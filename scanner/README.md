# 观察池日报（自动扫描）

每个交易日自动扫描 [`watchlist.txt`](../watchlist.txt) 里的股票，把结果写进 [`scan.md`](../scan.md)，并发一封邮件。

**纯固定公式，没有任何 AI 参与。** 计算方法和本仓库两个 TradingView 指标完全相同，所以数字可以和图表上的面板对照：

- [第一性原理面板](../indicators/first-principles-panel/)：均线位置与排列、结构（突破/跌破前 20 根高低）、量比、ATR14、相对基准强弱、近低/近高
- [位置与风险面板](../indicators/position-risk-panel/)：离 MA20/MA50 多远（% 与 ATR 倍数）、一年位置、涨/跌量比、ATR 分位、止损/目标/风险收益比、未回补跳空缺口（逐根移植 Pine 逻辑：先移除已回补的缺口，再记录新缺口，最多保留最近 10 个；输出个数及收盘上方 / 下方最近的缺口边沿。只用约两年日线计算，若两年前还有未补缺口，个数可能比 TradingView 少）

此外还会对比前一天，列出 **今日变化**：新突破近高 / 新跌破近低、收盘上穿或下穿 MA20/50/200、均线排列变化、相对强弱由弱转强或由强转弱。

## 修改观察池

编辑仓库根目录的 `watchlist.txt`，一行一个 Yahoo Finance 代码，可选“逗号 + 基准代码”：

```
# 注释行以 # 开头
MU              # 不写基准，默认 SOXX
SIVE.ST, ^OMX   # 瑞典股票，用 OMX 斯德哥尔摩 30 指数做基准
```

代码写法以 Yahoo Finance 网站为准：美股直接写代码；瑞典加 `.ST`，港股如 `0700.HK`，A 股如 `600519.SS` / `000001.SZ`；指数前面带 `^`。

上市时间短的标的（比如 DRAM 只有约半年数据）照常计算：不够 200 根时 MA200 为空（和 Pine 一样按 na 处理，均线位置/排列会显示为“夹在均线间 / 均线纠缠”），一年位置按全部已有 K 线计算，并在表格下方备注“数据不足”。某只代码拿不到数据时，该行显示“数据缺失”，不影响其他标的。

## 运行时间

- 自动：**北京时间周二至周六 09:45**（GitHub cron `45 1 * * 2-6`，UTC）。美股收盘是北京时间 04:00（夏令时）或 05:00（冬令时），所以每次运行时，上一个美股交易日都已收盘。
- GitHub 的定时任务高峰期可能延迟几分钟到几十分钟，属正常现象。

## 什么时候会跳过（不发信、不更新 scan.md）

每次运行先找出“上一个已收盘的美股工作日”（按纽约时间，收盘 20 分钟后才算），然后依次检查：

1. **休市**：用 NYSE 交易日历（`exchange_calendars` 的 XNYS）判断这一天是不是交易日。感恩节、独立日、耶稣受难日、元旦、圣诞等休市日直接跳过，日志显示“上一个美股交易日 …… 休市，无新数据，跳过”。
2. **没有新数据**：美股标的最新一根日线的日期不是这一天（比如 Yahoo 数据还没更新，或日历不可用时碰上假期），跳过。
3. **已经发过**：`scan.md` 里已经是同一个数据日期（比如手动又跑了一次），跳过，避免重复发信。

跳过时运行仍显示成功（绿色）。想忽略以上检查强制发一次：手动运行时勾选 **force**（见下），本地则加 `--force`。

举例（北京时间）：感恩节是美国周四，北京时间周五 09:45 那次运行会跳过；周六 09:45 那次照常发周五（提前收盘日）的数据。

## 手动运行

- 网页：仓库 **Actions** 标签 → 左侧选 **观察池日报** → 右侧 **Run workflow** → 选 `main` →（需要重发时勾选 **force**）→ **Run workflow**。
- 命令行：`gh workflow run scan.yml -R longyunBegin/trade`，强制重发加 `-f force=true`
- 本地：

  ```bash
  pip install -r scanner/requirements.txt
  python scanner/scan.py --no-email --force
  ```

  `--force` 跳过上面的“休市/无新数据/已发过”检查。会生成 `scan.md` 和 `scanner/out/email.html`（邮件预览，不提交）。若在盘中运行，会自动丢弃当天未收盘的那根 K 线。

## 需要的 Secrets

在仓库 **Settings → Secrets and variables → Actions** 里设置（邮箱和密码不要写进代码，仓库是公开的）：

| 名称 | 内容 |
|---|---|
| `GMAIL_USER` | 发件 Gmail 地址 |
| `GMAIL_APP_PASSWORD` | Gmail **应用专用密码**（Google 账号开启两步验证后，在“安全性 → 应用专用密码”生成的 16 位密码，不是登录密码） |
| `MAIL_TO` | 收件地址，多个用英文逗号分隔 |

三个中缺任何一个，脚本会跳过发信，只更新 `scan.md`，运行仍然算成功。配置齐全但发信失败（如密码错误）时，运行会标红，方便发现问题。

## 邮件样式

苹果式极简排版，点缀少量 [useLayouts](https://uselayouts.com/) 元素（暖米白底色、海军蓝文字、今日变化卡片顶部一条渐变细线、等宽小标签）。从上到下按重要程度排列：

1. **标题**：观察池日报 + 日期。
2. **今日变化**：只列有信号的标的，一行一只（代码 + 一句话），红涨绿跌；没有信号时只显示一行提示。
3. **总览**：一行一只，五列——代码、收盘、涨跌、趋势（多头 / 纠缠 / 空头）、风险收益比；蓝点表示今天有信号。
4. **明细卡片**：头行是代码、名称、收盘和涨跌；下面一块重点行是趋势、结构、风险收益比和止损 / 目标；再下面是次要读数（均线位置、量能、相对强弱、离 MA20 / MA50、一年位置、近低 / 近高、ATR14、涨跌量比、ATR 分位），左边标签右边数值。只有“偏离大”这类有含义的情况才加标签。
5. **页脚**：数据日期、数据源、不构成投资建议。

手机上不需要左右滑动，支持深色模式（iOS 邮件等）；不支持渐变的邮箱会显示纯色细线。

Gmail 会把超过约 100KB 的邮件折叠（显示“查看完整邮件”）。每只标的约 5KB，目前 9 只约 58KB；超过 95KB 时，脚本会自动把排在后面的明细卡片换成精简版（只保留头行和重点行），`scan.md` 不受影响。

## 数据来源

Yahoo Finance（通过 `yfinance`），免费，取日线收盘、约两年历史。价格为拆股调整、未做分红调整，和 TradingView 默认显示一致。免费数据偶尔会延迟或出错，若某天数字明显不对，以券商或 TradingView 为准。

想换成付费数据源（Polygon、Tiingo、券商 API 等），只需要改 `scanner/scan.py` 里的 `fetch_daily()` 函数，让它返回同样格式的日线表格（日期索引，Open/High/Low/Close/Volume 五列），其余计算和邮件都不用动。
